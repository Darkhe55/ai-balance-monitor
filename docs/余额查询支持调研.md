# AI 余额监控：余额查询支持调研报告

> 调研日期：2026-11-09
> 调研方式：抓取各平台官方文档（`webfetch`），并对部分站点直接抓取官方 **OpenAPI spec / API 参考** 核实端点与响应结构。
> 当日 `websearch` 接口不可用，部分官网（Together / Groq / Perplexity / AiHubMix 等）返回 403 或超时，
> 或本地网络无法建立连接（Hugging Face 等），无法进一步核实，已如实标注在对应条目。
>
> 结论分级：
> - **已经加入支持**：工具内可正常新增并查询余额/额度
> - **确认无法支持**：官方确认无公开余额 API（或接口已下线），本工具无法接入
> - **等待开发**：官方有余额 API，但尚未实现入口

## 三、等待开发

以下平台经核实**官方确实提供余额查询 API**，可作为后续新增入口的候选：

### ✅ 已加入支持（2026-11-09 已实现）

- **Novita AI**：官方余额接口 `GET https://api.novita.ai/openapi/v1/billing/balance/detail`
  （Bearer API Key，字段单位 1/10000 USD）已接入为独立入口。
- **fal.ai**：官方账户账单 `GET https://api.fal.ai/v1/account/billing?expand=credits`
  （Authorization: Key，需 READONLY/BILLING 权限 Key）已接入为独立入口。

### 高优先级候选（已确认官方余额接口，尚未实现）

- **Hyperbolic**：`GET https://api.hyperbolic.xyz/v2/customer/balance`
  - 认证：`Authorization: Bearer <API Key>`（官方 OpenAPI spec 已核实）
  - 响应 `AccountBalance`：`balanceCents`（账户信用余额，单位**美分**，÷100 = USD）、`maxOverdraftCents`（最大透支额度）
  - 定位：海外 AI 云（GPU 云 + 开源模型推理，OpenAI 兼容），与 Novita/fal 同类 → 归「第三方」分区

- **Vast.ai**：`GET https://api.vast.ai/api/v0/users/current`
  - 认证：`Authorization: Bearer <API Key>`（官方 OpenAPI spec 已核实）
  - 响应含 `balance`（当前余额，美元 float）、`email`、`id` 等
  - 定位：海外 GPU 云市场（预付费 credits）→ 归「第三方」分区

### 待确认：Hugging Face（低优先）

- 有 billing usage API（`/api/organizations/{org}/billing/usage/inference?...`）和 `/api/credits`
  （端点存在，未认证返回 401，响应结构待实测；当日本地网络无法建立连接，未能进一步核实）
- HF 免费账户无固定余额，credits 主要用于 Inference Providers，优先级较低

### 中优先级：Fireworks AI

- 官方有 `Get Account Usage` / `Get Billing Summary` 接口
- 但需要**账户级 / 管理员或带账单权限的服务账号**，不是普通 serverless API Key
- 接入复杂度接近「OpenAI Admin Key」入口，需要用户提供管理员凭证

### 待实测：GLM（智谱）

- 官方余额/配额接口状态不稳定（见上），需要一把真实套餐 Key 实测当前响应结构后，才能修正 `GlmProvider` 解析并恢复支持

### 第三方网关补充说明

- 绝大多数 OpenAI 兼容中转站（AiHubMix、API2D、OpenAI-SB、UniAPI、Helio 等）的余额查询
  走 `/v1/dashboard/billing/usage` + `/v1/dashboard/billing/credit_grants`，
  现有 **OneAPI / NewAPI 网关**入口已探测这两个端点，因此**无需新增独立入口**，配置 Base URL 即可复用。
